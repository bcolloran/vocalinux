# MVP Notes

## Summary

The preview-first MVP is now in place and usable. The project is no longer at
the planning/foundation stage; it has crossed into a real end-to-end preview
workflow with HTT-specific behavior, explicit review actions, and new settings.

## What Shipped

### Transcript Output Control

- added `TranscriptOutputController`
- added `PendingTranscriptStore`
- normalized output modes to:
  - `immediate_injection`
  - `preview_deferred_injection`
- preserved legacy config migration for older output-mode values

### Preview UI

- added a standalone GTK preview window
- added `Commit`, `Discard`, and `Copy`
- wired tray + controller updates into the preview window
- added preview placement settings:
  - horizontal: left / center / right
  - vertical: top / middle / bottom

### HTT Flow

- HTT now opens the preview window immediately on press
- HTT release commits the current live preview text
- HTT `Esc` cancels the session and closes the preview flow
- late finalized callbacks are suppressed until idle after HTT commit/cancel

### Injection / Reliability

- xdotool typing speed is now configurable through settings
- default xdotool delay is now `0 ms`
- xdotool chunking was increased to reduce long-text overhead
- removed synthetic `Escape` after xdotool typing because it could cancel HTT
  and trigger duplicate injection

### Settings / Config

- HTT is now the default shortcut mode for new configs
- preview placement settings are persisted
- text injection delay is persisted
- sound test button exists in Settings

### Installer / Uninstaller

- uninstall now defaults to keeping user settings/data
- installer persists install choices to installer metadata
- installer can reuse prior install choices
- current follow-up: make the installer metadata easier to discover and reuse
  when the dedicated metadata file is missing

## What We Learned

### 1. HTT is not the same as generic preview mode

The original plan treated preview mode mostly as a deferred version of the
existing finalized-text pipeline. In practice, HTT needed its own release-time
commit behavior based on live preview text, not only finalized transcript text.

### 2. A standalone preview window was the right MVP choice

Attaching a UI to the tray would have cost more complexity than it returned for
the first pass. The utility-window approach got us a testable, debuggable MVP faster.

### 3. Injection timing bugs can come from support code, not only recognition

One duplicate-injection path was caused by our own post-injection synthetic
`Escape`, not the recognizer. That reinforced the need for lifecycle logging at
the tray / controller / injector boundaries.

### 4. Installer metadata should be treated as user-facing state

Even though install choices are not runtime dictation settings, users expect
reinstalls to remember them. Visibility and fallback behavior matter here.

## Current MVP Assessment

### Completed

- preview-first transcript buffering
- explicit commit/discard review flow
- HTT live preview release flow
- configurable preview placement
- configurable xdotool typing delay
- logging around new MVP features

### Good Enough For MVP

- standalone preview window instead of tray-attached preview pane
- xdotool-based commit path even though it still behaves like typing

### Still Rough

- installer reuse flow needs hardening for older installs and easier discoverability
- xdotool injection is faster now, but still not instant
- more real-session testing is needed across desktop/session variations

## Recommended Next Steps

1. Finish hardening installer metadata persistence and fallback loading.
2. Run another manual validation pass for HTT on the target desktop session.
3. Decide whether to pursue a faster non-typing injection path.
4. Decide whether a tray-attached preview is still worth doing after MVP.
